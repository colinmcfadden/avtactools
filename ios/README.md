# EZ/PZ for iPhone and iPad

The Swift app. Its plan, the steps and the owner's decisions are in [`docs/IOS_PLAN.md`](../docs/IOS_PLAN.md); the rules every
native client follows (the web is the reference, the fixtures are the contract) are in [`AGENTS.md`](../AGENTS.md) §17.

**Where it stands:** I1, the pure core's first part (the model, MGRS and the planning maths, held to the fixtures), and I3, the map
(MapLibre, three base maps, the readout, search, GPS, the MGRS grid, the long-press menu) in the iPhone's and the iPad's frames. The
panels arrive from I4; sign-in from I2.

```
ios/
├─ EZPZ.xcodeproj         the app target (its sources are the App folder, kept in step by Xcode itself)
├─ App/                   the composition root
├─ Config/Version.xcconfig  the app's own version, its API majors, the placeholder bundle id
├─ Packages/EZPZCore/     the pure modules: Foundation only, tested with `swift test` on the Mac
│   CoreJS                what JavaScript does that every port must do the same way: JSONTree, Js, JsNumber
│   CoreModel             android/core-model: the diagram, routes, points, threats and their sets, units, aircraft, weather
│   CoreGeo               android/core-geo: MGRS both ways, the grid, reading a place, grid sharing, great circles
│   CorePlanning          android/core-planning, and the web's backstops, graphic scale, FLOT and phase lines
│   CoreMap               feature-map's plain arithmetic: styles, readout, projection, the grid's scene, the FAA charts
│   DesignTokens          Tokens.swift, generated by contracts/scripts/tokens.py
│   CoreTesting           reads contracts/fixtures, compares JSON with a tolerance
├─ Packages/EZPZFeatures/ what may import UIKit and MapLibre (MapLibre Native iOS 7.0.0)
│   DesignSystem          the palettes as SwiftUI colours, Liquid Glass over the map, toasts
│   FeatureMap            MapStore, the MapLibre view, the crosshair, readout, grid labels, Layers, search, the map's menu
└─ Scripts/               number_text_sample.mjs, the Node check of JsNumber.toText
```

## Build and test

Xcode 26 or later (the owner's Mac has 27.2).

```bash
swift test --package-path ios/Packages/EZPZCore
```

```bash
swift format lint --strict --recursive ios/App ios/Packages/EZPZCore/Sources ios/Packages/EZPZCore/Tests ios/Packages/EZPZCore/Package.swift ios/Packages/EZPZFeatures/Sources ios/Packages/EZPZFeatures/Package.swift
```

```bash
xcodebuild -project ios/EZPZ.xcodeproj -scheme EZPZ -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

The app talks to the server named by `EZPZ_API_URL` in `Config/Version.xcconfig` (production by default). If Xcode or `swift package resolve`
hangs fetching MapLibre (it has in an agent's sandbox), download the zip its `Package.swift` names with `curl` into SwiftPM's artifact cache.

Or open `ios/EZPZ.xcodeproj` in Xcode and run the EZPZ scheme on a simulator. Signing waits on the owner's Apple team and bundle id
(docs/IOS_PLAN.md §15).

**`JsNumber.toText` against Node**, when the number writer changes (Node 22):

```bash
node ios/Scripts/number_text_sample.mjs /tmp/number_sample.json
```

```bash
EZPZ_NUMBER_TEXT_SAMPLE=/tmp/number_sample.json swift test --package-path ios/Packages/EZPZCore --filter everyNumberNodeWrote
```

On 2026-11-21, 461,755 doubles were written exactly as Node writes them.
